# 计算机网络与通信：专题笔记

## 专题一：分层模型与物理链路

OSI 七层和 TCP/IP 分层的关键不是背名称，而是理解封装：应用数据逐层添加首部，接收端逐层去除。物理层关心比特、带宽和信号；数据链路层负责相邻节点的帧传输；网络层负责跨网络寻址和转发；传输层为进程提供端到端服务。

带宽、传播时延和传输时延要区分。传输时延近似为 $L/R$，传播时延为 $d/v$；窗口协议的吞吐量还受往返时延约束。题目给链路长度、速率和帧长时，先列这几个量再作比较。

## 专题二：数据链路、交换与 VLAN

以太网帧包含目的/源 MAC、类型或长度、数据和校验字段。交换机通过自学习表把帧转发到对应端口，未知目的或广播帧会泛洪。生成树协议用于避免二层环路，VLAN 则用标签把一个物理交换网络划分为多个逻辑广播域。

可靠链路常用 CRC 检错；滑动窗口协议用确认、序号和超时实现流水线。停等协议简单但带宽利用率低，回退 N 帧会重传一段窗口，选择重传只重传丢失帧。作图时要标发送窗口、确认号和超时点。

## 专题三：IP 寻址、路由与 IPv6

IPv4 前缀 `/n` 表示前 n 位为网络号，主机数通常为 $2^{32-n}-2$（需考虑特殊子网）。最长前缀匹配决定路由表中优先使用哪条路径。子网划分题先把地址写成二进制，再根据主机数向上取整分配主机位。

路由算法中，距离向量基于 Bellman-Ford，链路状态基于全网拓扑和 Dijkstra。NAT 改写地址和端口缓解地址不足，但会影响端到端可达性。IPv6 使用更长地址、邻居发现和无状态自动配置，题目要注意压缩书写规则。

## 专题四：TCP/UDP 与拥塞控制

UDP 无连接、开销小，可靠性由应用自行实现；TCP 通过三次握手建立连接、序号与确认保证可靠有序传输。滑动窗口由接收窗口和拥塞窗口共同限制，实际可发送数据量取两者较小值。

拥塞控制包含慢启动、拥塞避免、快速重传和快速恢复。发生超时通常把拥塞窗口降到较小值，收到重复 ACK 则可能触发快速重传。计算窗口变化时按 RTT 分段画时间轴，明确每一轮的阈值和丢包事件。

## 专题五：DNS、HTTP 与网络安全

DNS 用层次化域名解析把名称映射为 IP，递归解析器可能缓存结果，TTL 决定缓存有效时间。HTTP 是请求—响应协议，持久连接、缓存和状态码决定应用性能。HTTPS 在 HTTP 之下加入 TLS，使用证书验证身份并协商会话密钥。

安全题可按机密性、完整性、身份认证和可用性四个目标分类。对称加密适合大量数据，非对称加密适合密钥交换和签名，哈希用于完整性校验。常见失分点是把编码、加密和哈希混为一谈，或忽略证书链和随机数。

## 应试与抓包路径

先判断报文所在层，再沿封装顺序写首部；地址题先求网络号和广播地址；TCP 题画序号/确认号时间轴；DNS/HTTP 题注明端口、缓存和状态码。配合[课程复习提纲](resources/network-review-outline.pdf)和[第一、二部分资料](resources/network-part1.pdf)逐章核对。

## 专题六：子网划分与路由表计算

子网题可以按“需求 → 主机位 → 前缀 → 地址范围”的顺序做。若一个子网至少需要 \(h\) 台可用主机，应满足 \(2^m-2\ge h\)，其中 \(m\) 是主机位数；前缀长度就是 \(32-m\)。得到前缀后，再用块大小确定网络地址和广播地址。不要只记住“减 2”，还要检查题目是否允许全 0、全 1 子网，以及是否使用点到点链路的特殊规则。

路由表题要区分“路由选择”和“下一跳转发”。收到数据报后，路由器先对目标地址做最长前缀匹配，再查下一跳和出接口，最后递减 TTL 并重新计算首部校验。若题目同时给出默认路由和更具体的子网路由，应优先选择前缀更长者；若前缀相同，再比较管理距离或度量。

## 专题七：可靠传输的序号与窗口

停等、回退 N 帧和选择重传的共同基础是序号空间、确认机制与超时重传。分析题时先写发送窗口和接收窗口的边界，再标出丢失、乱序、重复 ACK 和超时事件。累计确认表示“此前连续数据已收到”，选择确认则可能只确认某个区间，二者不能混写。

若序号字段有 (k) 位，序号空间为 (2^k)。滑动窗口必须小于序号空间的一定范围，才能区分“旧帧”和“新一轮的同号帧”。考试中若题目问窗口上限，应先判断协议属于回退 N 帧还是选择重传，再套用对应约束。

## 专题八：TCP 拥塞控制的时间线

TCP 题建议画两条曲线：拥塞窗口 (cwnd) 和慢启动阈值 (ssthresh)。连接初期慢启动按 RTT 快速增长，达到阈值后进入拥塞避免；三次重复 ACK 通常触发快速重传，超时则说明拥塞更严重。每遇到一次丢包，都要记录是超时还是重复 ACK，因为两者对阈值和窗口的更新不同。

吞吐量估算不能只看链路带宽，还要考虑窗口大小和往返时延。若发送窗口小于带宽时延积，链路会出现空闲；若接收窗口更小，发送端即使拥塞窗口很大也无法继续发送。抓包分析时可同时观察 ACK 间隔、重传段和窗口通告，定位瓶颈在网络拥塞还是接收端处理能力。

## 专题九：DNS、HTTP 与 TLS 的一次完整访问

浏览器访问一个 HTTPS 页面时，通常经历本地缓存检查、DNS 解析、TCP 建连、TLS 握手和 HTTP 请求。每一步都可能有独立的延迟和失败原因。DNS 的 TTL 只决定缓存有效期，并不保证服务器始终可达；TLS 证书验证负责身份和密钥协商，不能替代 HTTP 层的权限控制。

复习状态码时可按问题类型归类：2xx 表示成功，3xx 表示重定向，4xx 多为请求或权限问题，5xx 多为服务器处理问题。分析缓存题时要同时看 Cache-Control、ETag、If-None-Match 和响应状态码，不能把“浏览器没有重新下载”简单等同于“服务器没有参与”。

## 抓包与排障清单

遇到“能 ping 但网页打不开”，按 DNS → TCP 端口 → TLS → HTTP 的顺序检查；遇到“局域网能访问、跨网段失败”，检查默认网关、路由表、ACL 和 NAT；遇到“偶发丢包”，同时记录时间、流量方向、无线信号和重传次数。每次排障保留过滤条件、关键报文编号和结论，才能把抓包变成可复现的实验记录。
