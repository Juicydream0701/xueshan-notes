# 计算机网络：分层、协议与性能计算

网络题先确定所在层次，再区分控制信息和数据传输。遇到协议比较题，按服务对象、寻址方式、可靠性、时延和典型场景回答。

## 1. 分层模型与封装

应用层数据经过传输层、网络层和数据链路层逐层封装，接收端逆向解封装。每层都有自己的首部和寻址：端口号、IP 地址、MAC 地址分别服务于不同范围。分层的价值是隔离变化，但跨层问题需要追踪完整路径。

## 2. 数据链路层

以太网使用帧、MAC 地址和交换机转发。冲突域、广播域和 VLAN 是常见概念。CRC 检错能发现大量传输错误，但不能自动纠正。交换机学习源 MAC，依据目的 MAC 决定转发、过滤或泛洪。

## 3. IP 与路由

IPv4 地址由网络号和主机号组成，子网掩码决定边界。给定地址和掩码时，先按位与求网络地址，再计算广播地址和可用主机范围。CIDR 聚合要求前缀连续且地址块大小为 (2^k)。

路由表采用最长前缀匹配。静态路由、距离矢量和链路状态算法的收敛方式不同；Dijkstra 用于链路状态，Bellman-Ford 思想用于距离矢量。

## 4. 传输层

TCP 通过序号、确认、重传、滑动窗口和拥塞控制提供可靠字节流。三次握手同步双方初始序号，四次挥手处理半关闭。UDP 无连接、开销小，可靠性由应用自行实现。

窗口和吞吐题要区分接收窗口、拥塞窗口和往返时延。慢启动阶段拥塞窗口指数增长，达到阈值后转为线性增长；丢包后根据 Reno 等算法调整。

## 5. 应用层协议

DNS 把域名解析为地址，HTTP 使用请求/响应模型，HTTPS 在 HTTP 与 TCP 之间加入 TLS。缓存、持久连接和代理会改变实际时延。分析抓包题时按 DNS、TCP、TLS、HTTP 的顺序标记报文。

## 6. 性能与排错

链路利用率取决于传播时延、传输时延、排队和处理时延。吞吐率受瓶颈链路限制；丢包、RTT 增大和窗口过小都会降低有效吞吐。排错顺序建议：物理连接 → 链路状态 → IP 配置 → 路由 → 端口监听 → 应用响应。
