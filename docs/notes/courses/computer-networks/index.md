## 题目训练：把协议写成可检查的过程

### 题 1：子网划分

某部门得到 `192.168.10.0/24`，需要划分为 4 个规模相同的子网。写出每个子网的网络地址、可用主机范围和广播地址。

**解题要点**：4 个子网需要借 2 位，前缀变为 `/26`，块大小为 (2^{32-26}=64)。四个网络地址依次为 `192.168.10.0`、`.64`、`.128`、`.192`；每个子网的可用主机范围去掉网络地址和广播地址。答题时写出“借位—块大小—范围”三步，避免只写结果。

### 题 2：滑动窗口吞吐量

链路速率为 (R)，往返时延为 (RTT)，发送窗口为 (W) bit。忽略处理和排队时，窗口受限的吞吐量近似为

$$
T\le \min\left(R,\frac{W}{RTT}\right).
$$

若 (rac{W}{RTT}<R)，说明发送端还没有填满带宽时就必须等待确认；增大窗口或降低 RTT 才能改善利用率。不要把“链路带宽”直接当成“实际吞吐量”。

### 题 3：TCP 丢包时间线

已知慢启动阈值为 16 MSS，拥塞窗口从 1 MSS 开始，每个 RTT 无丢包时按慢启动增长；当拥塞窗口达到阈值后转入拥塞避免。若第 5 个 RTT 发生超时，应记录新的 `ssthresh` 与 `cwnd`，再从下一轮重新开始。若改为收到 3 个重复 ACK，则属于快速重传分支，窗口调整规则不同。作图时至少画出 RTT、`cwnd`、`ssthresh` 和丢包事件四条信息。

### 题 4：一次 HTTPS 访问的排障顺序

浏览器能解析域名但页面打不开，按 DNS、TCP、TLS、HTTP 顺序排查：先确认 DNS 响应中的地址和 TTL；再确认目标端口是否完成 TCP 三次握手；随后检查 TLS ClientHello、证书链和时间有效性；最后看 HTTP 状态码与响应头。`ping` 成功只能说明某种 ICMP 路径可达，不能证明 TCP 443 或应用服务正常。

## 课程复盘表

每次做完一道综合题，至少留下四列：**题目条件、所在层、关键状态、可验证结论**。例如 TCP 题的“关键状态”是序号、ACK、窗口和计时器；路由题的“关键状态”是最长前缀、下一跳和 TTL。这样复习时可以从错误所在的层定位，而不是重新通读整章。
