# 中断系统

中断让 CPU 在正常程序运行过程中响应异步事件。它适合处理外部输入变化、定时到期和通信完成；不应把耗时工作全部放进中断服务程序。

## 80C51 中断源与向量

标准 80C51 有 5 个中断源，80C52 增加定时器 T2 中断。

| 中断源 | 请求标志 / 控制 | 向量地址 |
| --- | --- | --- |
| 外部中断 0 | `IE0`、`IT0` | `0003H` |
| 定时器 0 溢出 | `TF0` | `000BH` |
| 外部中断 1 | `IE1`、`IT1` | `0013H` |
| 定时器 1 溢出 | `TF1` | `001BH` |
| 串行口 | `RI` 或 `TI` | `0023H` |
| 定时器 2（80C52） | `TF2` / `EXF2` | `002BH` |

向量处通常放一条 `LJMP`，再跳到实际服务程序，以免服务程序挤占相邻向量位置。

## 使能与优先级

IE 的 `EA` 是总开关；各个 `EX0`、`ET0`、`EX1`、`ET1`、`ES`（以及 8052 的 `ET2`）控制单个来源。所有相关允许位都打开后，中断请求才可能被 CPU 接受。

IP 为中断源设置高、低两个优先级。高优先级可以打断低优先级服务程序；同级请求按固定查询顺序处理，同级不能互相嵌套。优先级只决定 CPU 如何安排请求，不会代替外设标志的处理。

外部中断触发由 TCON 的 `IT0/IT1` 选择：0 为低电平触发，1 为下降沿触发。电平触发源需要在返回前解除有效电平，否则请求会再次出现。

## 响应与返回

CPU 完成当前指令后查询并接受请求，保存返回 PC，转入对应向量，执行服务程序，最后由 `RETI` 返回并恢复中断控制器的服务状态。硬件不会替程序自动保存所有通用寄存器。

标准服务流程：

1. 保存服务程序要改动且主程序仍依赖的寄存器与 PSW。
2. 读取或确认中断来源；串行口向量需检查 RI 和 TI 分别处理收、发事件。
3. 尽快清除或服务请求标志，并将数据写入缓冲区。
4. 恢复现场，使用 `RETI` 返回。

## 编程模板

```asm
        ORG 0000H
        LJMP MAIN
        ORG 000BH
        LJMP TIMER0_ISR

MAIN:   MOV  TMOD, #01H
        SETB ET0
        SETB EA
        SETB TR0
WAIT:   SJMP WAIT

TIMER0_ISR:
        PUSH ACC
        PUSH PSW
        ; 处理定时事件并按需要重装初值
        POP  PSW
        POP  ACC
        RETI
```

该模板只展示入口和现场保存。定时器初值、标志清除方式及重装时机要按具体工作模式设计。

## 可靠性检查

- 共享变量是否会在主程序和中断之间同时读写？多字节变量是否需要短暂关中断保护？
- 服务程序是否足够短，是否可能在中断中等待串口或做长循环？
- 是否正确处理 RI、TI 这类通常由软件清除的标志？
- 是否保存了程序真正会改动的寄存器，并按后进先出的顺序恢复？
- 是否使用 `RETI`，并确保外部电平请求在退出时已解除？
