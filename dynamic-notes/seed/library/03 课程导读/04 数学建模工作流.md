# 数学建模：从题意到可交付结果

数学建模的核心不是把算法堆得越复杂越好，而是让假设、变量、模型、验证和结论彼此对应。完整的专题、算法讲义和 PDF 入口见[静态主站数学建模区](https://juicydream0701.github.io/xueshan-notes/notes/campus/math-modeling/)。

## 六步工作流

1. **读题与改写**：把背景叙述改成目标、约束、输入和输出。
2. **定义变量**：给每个变量写单位、范围和可观测来源。
3. **提出假设**：只保留会影响结论的假设，并说明可能造成的偏差。
4. **建立基线模型**：先做可解释、可计算的模型，再考虑复杂方法。
5. **验证与敏感性分析**：划分训练/验证数据，检查参数变化是否改变结论。
6. **写作与复核**：图表先服务于问题，结论回到题目，代码、数据和单位保持可复现。

## 题型定位

- 有时间序列和趋势：先看回归、指数平滑或状态空间；
- 有类别标签：先做基线分类，再比较评价指标；
- 有资源分配：看线性/整数规划和约束是否完整；
- 有方案排序：先明确指标方向、权重与稳健性；
- 有空间、路径或网络：先画图，再决定图论、优化或仿真方法。

## 比赛期间的最低保障

每个成员都应能说明当前模型的输入、输出、假设、误差来源和下一步验证。提交前统一检查：文件名、图例、单位、引用、随机种子、代码运行说明和结论是否互相一致。
